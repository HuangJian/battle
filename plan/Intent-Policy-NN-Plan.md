# Intent-Policy NN 计划 — 基于策略意图的神经网络（取代并超越 God-AI）

> 状态：方案定稿（2026-08-26，基于 AI-No-Items-Warmstart.md 全案讨论收敛重写）
> 受众：后续执行开发的 agent
> 上游事实基线：BC 三形态（wins / wins+人像 / wins+DAgger）均 0% WIN；RL 旧谱系平台 ≈10%；
> God-AI 现基线 ≈ classic 89.5% / hard 75.9%（摘道具后 ~75%）/ chaos ≈70%
> 关联：DECISIONS §247–§250（M1 探针 / M2 纪元 / M3 回环）；AGENTS §2/§6/§7/§14

## 0. 为什么重写（一句话背景）

**move/fire 层级的学习已被四项证据判定为死路，且归因已钉死（勿再模糊归为"表达墙"）**：
① BC 三种语料形态精确 0 胜（开环误差复合 0.476^500≈0；[DECISIONS §249/§250](file:///d:/github/battle2/DECISIONS.md#L1685-L1698)、nn.progress §15.3）= **③监督级联**的量化表现；
② M1 探针"基地高压桶"分歧率 74.6% **且特征表完整**（[DECISIONS §247](file:///d:/github/battle2/DECISIONS.md#L1670-L1675)）→ 归因 **①标签选择 / ③监督方式为主嫌疑**；**②表达墙降级为"嫌疑"（Q1）**：特征表完整只证"预注册特征俱在"，**单帧 obs 无时间堆叠（除意图注入外），时序型表达缺口不能排除**。另有支持性论据：97% 静默分歧 + move acc >> 随机 ⇒ ①/③ 主导的可能性确实更高——但到 M0.5 探针（§3.6）给出逐桶可学习余量之前，"已排除②"不许再出现；
③ RL 基地防守零梯度（v7 baseSafety 饱和，81% 败局为 base_destroyed）→ 奖励层的独立第四条病。
**药方**：把可学对象从 per-tick move/fire 上移到 planner 内部意图——**治 ①（意图标签替代逐 tick 贪心输出，噪声更低）与 ③（监督级联）**；**主机制从"级联深度收窄"改为"错误可恢复性"（P0-3）**：意图错一窗 ≠ 灾难——执行器仍按语义走位、reflex 仍在躲弹、下个 replan 窗口从真实状态重选；深度 /24–50（vs per-tick）与 /2.4–5（vs K=10）只是**次要量化、非因果论证**（0.9^208 ≈ 10⁻¹⁰，深度叙事下全灭依旧成立——真正的治疗方案是可恢复性，由 M7① 意图扰动鲁棒性曲线直接量化）；天花板由"词表×执行器"界定，交 M7① 探针实测；低层执行交脚本、守家快环交硬代码。

**级联深度口径（P2-1）**：相对 per-tick 全链决策（SHIPPED hard `thinkInterval=1`，[params.ts:2417](file:///d:/github/battle2/src/ai/god/params.ts#L2417)）为 **/24–50**；相对 move-BC 的 K=10 决策采样为 **/2.4–5**（两种口径并列，防后世复核卡住）。
**在案风险**：仅把全链放缓 2× 已实测 −2.8pp（[DECISIONS §231](file:///d:/github/battle2/DECISIONS.md#L1273-L1282)：thinkInterval=2，691/2100 翻转）。本架构豁免因素 = reflex 仍逐 tick 硬代码 + 执行器逐 tick 读 World——但该风险必须显式入账（§9 R0），由 M7① replan 扫描实测，**不得静默假设**。

本计划取代 AI-No-Items-Warmstart.md 的 M4+ 方向；该文档 M0–M3 及其记录保留为历史事实。

## 1. 目标与边界

| 项 | 内容 |
|---|---|
| 目标 | IntentPlayer（意图策略 NN + 脚本执行器）hard 胜率**先过 50% gate，再冲超越 God-AI ≈76%** |
| 天花板定理（务必记住） | 表达力上限 = **词表 × 执行器策略库**；RL/BC 只决定逼近程度。God-AI 行为必须能被词表 100% 映射（表达覆盖测试），否则"超越"无从谈起 |
| 能超越什么 | RL 优化的是**意图选择函数**（含切换时机/承诺/目标选择）——这个函数空间 > God-AI 的 per-tick 贪心 if-else（治摇摆、学它没有的映射） |
| 不能超越什么 | RL 不能自发发现词表外新意图（CPU 预算内 option-discovery 不现实）。词表缺口靠**取证驱动的补词/分裂流程**（§7-M9），不靠 RL |
| 最终验收与停止线（Q9） | M9 后 **60-seed 封闭评测 WIN ≥78%** 判"超越"达成；连续 **3 轮扩词 WIN 无提升 → 显式停止并归档"本路线天花板实测"**；下限目标 = **≈76% 不劣 + 更小可推理**（即便不超，也交付可比 God-AI 的可蒸发部署体） |
| 硬约束 | TS 可复现（BN-free、ReLU+softmax）、纯 CPU 训练、确定性、One Author、无新依赖、不破坏 classic/chaos 回归门；**推理预算按 §4.3 实测口径（P0-1 修正：单前向 ≈34–56ms，非亚毫秒；headless 评估不限、实机部署另立 Worker 卸载决策）** |

**超越来源显式化（I5，评审修正版）**：
- **A 臂（纯 God-AI 意图 BC）封顶于词表×执行器天花板，不提供"必超"承诺**——但它仍可能小幅优于 God-AI 本体：承诺期+平滑选择函数本身优于 per-tick 贪心（摇摆病正是这么治的）。A 臂的上界是天花板，不是 God-AI 的 76%；
- **超越的主力来源 = B 臂（人像 oracle，守家桶优于 God-AI 的黄金样本）+ M8 RL（优化切换时机/承诺/目标选择）**。**B 臂为必备交付**（非可选项）、M8 为条件交付；
- **B 臂降级分支（Q3，写死）**：若 M2 的 counterfactual oracle 增益量化（§5.2）判 **B ≤ A** → B 臂降级为可选、超越主力改 **M8 RL 独占**，并在 DECISIONS 记录改判依据——"人像守家更优"目前是假设，不配做无条件的支柱；
- M7① 天花板探针是天花板的**下界测量仪器**（规则选择器 ≠ 最优选择器），不是天花板本身——探针 <76% 只说明"词表×执行器连 God-AI 行为都装不下"，必须返工；探针 ≥76% 才打开超越通道。

## 2. 架构总图

```
obs(14×26×26 + 19 scalars) → 意图策略网（复用 StudentNet 主干 + 三头）
                 + 运行时注入特征[当前意图 one-hot + 意图持续时长]（CoordConv 注入先例，免 schema bump）
        ↓ 每 replan 周期（24–50 tick，预注册）评估
 ① 意图头 8 类（INTERCEPT / RETURN-DEFENSE / HUNT / HOLD-LANE / CLEAR / PICKUP / CRUISE / ESCAPE）
 ② 目标敌头 5（none/e0..e3，槽序固定）  ③ 目标锚头 ≤16 角色（role→本关坐标由执行器解析，§3.4）
（三头按**父意图→激活头矩阵**屏蔽：非激活头不产生梯度也不被解释，§3.5/P0-4）
        ↓ 执行器保持当前意图（承诺期），直到切换条件（新意图≠旧 AND argmax 边际≥阈值，预注册）
 执行器策略库（God-AI 全部 SHIPPED 策略 + 候选挂靠，30–50 细分支；上下文规则分派；带 A/B 账本准入）
        ↓
 硬代码 reflex（闪避/贴墙/转体，永不学习、**逐 tick 运行**——replan 只作用于意图选择层，P0-2 豁免因素）
（执行器**三层契约**：window-locked 主行为 / per-tick overlay / per-tick reflex——仲裁与"压制"标记见 §3.2，P0-5）
```

要点：
- **小学习词表 + 富执行器策略库**两层分离：表达力由库保证（库全 ⇒ 天花板 ≥ God-AI），逼近成本由词表保证（8 类易学）。God-AI 自身即"大模式 + 内部 cascade 分工"，我们学"选模式"、脚本管"模式内"。
- 执行器内部分派仍带承诺期 + 分支准入（A/B 账本）。**残余组合病的主防线 = 执行器承诺期 + 账本分派**；RL 切换成本项只是条件性辅助（M8 可能不发生，不得倒置依赖，P3-6）。
- **摇摆收益的边界（Q6，防高估）**：承诺期只作用于**意图类切换频率**；执行器内 interceptBase/baseLaneSentry/defenseIntercept 等 sub-branch **每 tick 仍贪心重跑**（它们不是 reflex）。"治摇摆"的兑现面 = 意图类级，sub-branch 级摆动由 M6 走动统计实测；"级联深度"口径恒指**意图选择层 cadence**，与"全链决策间隔"是两个量，禁止混写。

## 3. 词表与策略库（M0 交付物）

### 3.1 8 主类（学习词表，已定案）

| 类 | 语义 | God-AI 挂靠（SHIPPED 部分） |
|---|---|---|
| INTERCEPT | 拦截进逼之敌 | §157 baseClearShotThreat、§165 T2a、§198 卫位导航、§146 集合点、§155 bulletLaneWait |
| RETURN-DEFENSE | 回防/据守锚点 | §179 紧急回防/冰冻优先 |
| HUNT | 主动追击 | S6 hunt / aggressive(freeze) |
| HOLD-LANE | 走廊/中路据守 | §195 钻探粘性、§193-C/D 火力门 |
| CLEAR | 清障开路 | §162 卡死破墙、§189 开局联通 |
| PICKUP | 被动拾取（仅自动生效项，无主动道具） | §156 freezePickup、§158 closePickup、§148 撤退拾取 |
| CRUISE/ENDGAME | 巡航与收尾 | endgame 参数组 |
| ESCAPE | 脱险自保 | dodge 基线、t2aOutnumberedRetreat（候选） |

**ESCAPE（及其他短窗口类）的可学性裁决规则（P0-3，预注册，禁止临场）**：转移包含式采样（§5.1）下，
某类窗口绝对计数 < 200 的类自动降为 **reflex-only**（职能全交硬代码 reflex，学习词表相应收缩），
不做上采样补救——学习一个采样不到的类没有意义。**ESCAPE 与 reflex 的分工再澄清（Q10 小注）**：
dodge 弹道闪避本来就是 reflex 逐 tick 语义——若计数裁决把 ESCAPE 降级，其"意图层"语义（战术性撤退/
脱离包围）由 RETURN-DEFENSE/HOLD-LANE 的锚点目标参数承载，不留第三种解释。
**PICKUP 触发语义（Q10 小注）**：仅指"顺路/冰冻窗口内的被动守恒拾取"（§156/§158/§148 现有口径），
明确不因拾取而打断 HUNT/INTERCEPT 的追击语义——拾取范围与优先级沿用 God-AI 现常数，M0 写入签名词义。

**挂靠表补全要求（P0-5）**：§3.1 表必须补全为**全量候选行**（19 候选/细分支口径：aggro、engage、
firingLane、survive、midLaneHold、suicideReturn 等全部有归属行与三层标注）——目前只有代表性 § 引用，
**禁止"未挂靠候选"存在**；**INTERCEPT vs HUNT 的区分判据用状态谓词预注册**（敌是否威胁基地/是否在环上），
禁止人眼临场判；**suicideReturn 归 RETURN-DEFENSE 并携带"压制 dodge"调制标记**（§116/§117 **默认 OFF**——
它是"意图→reflex 调制通道必须规格化"的现成反例，见 §3.2）。

### 3.2 执行器策略库（脚本层，全量挂靠图）

- 全部 SHIPPED 策略按上表挂靠进对应主类（执行时由上下文规则分派）；
- **术语统一（P1-7④）**：本文"19→8 映射"实际是**细分支→（候选）→8 的两层映射**（`_lastBranch` 是细分支字符串，粒度细于 19 个 ActionId）——M0 交付物按两层口径命名，否则映射表验收范围被"19"错误收窄；
- **反向映射 = 意图→候选白名单（P0-1，与正向映射成对交付）**：白名单按**能力需要**定义而非正向镜像——INTERCEPT 白名单示例 = {interceptBase, baseLaneSentry, defenseIntercept, engage, aggro, closePickup(overlay), dodge(reflex)}；白名单分两层标注：**window-locked**（意图主行为）与 **per-tick overlay**（顺路拾取等跨意图辅助）；每意图白名单 M0a 定稿并预注册；
- **执行器三层契约与仲裁（P0-5）**：window-locked / overlay / reflex 三层；仲裁规则写死：reflex 覆盖移动默认成立，**例外只能经白名单内显式"压制"标记**（如 suicideReturn 压制 dodge——仅当其随 RETURN-DEFENSE 白名单启用时才生效）；PICKUP overlay 只在无直接威胁时生效；M6 加行为级仲裁测试（压制发生/不发生断言）；
- **19→8 映射归属规则（Q10 小注）**：候选命中多个意图时以**主意图 = 归属候选**为准，tagger 不得借此隐藏目标（enemy/anchor 标签照实落盘）；M6 导出 `ACTION_WEIGHTS` 映射时同步执行此规则；
- **5 项"立项未测"列为选择器架构下的重评候选**：§169 threatStickyTicks、§170 huntCommitTicks、
  §171 pathTargetMode、§172 bonusHuntBias、§173 baseDamageRecall——当年在"叠加进 per-tick 贪婪
  cascade"语境下搁置，在与"选择器+承诺期"组合下可能翻案，M0 产出重评实验清单；
- candidates（§216 否决的 4 候选）/ contract（§204）语义**进执行器分派规则**（本就是"分派"属性，不是全局开关）；
- 20+ 项实测阴性（starRush/coverage 五轮/中路初版等）**保持归档不重开**；
- 双人协作全家（§174–§181）不属单人意词语义，不入本计划。

### 3.3 表达覆盖测试（M0 验收项）

拿 God-AI hard 轨迹做意图序列标注，验证词表对 God-AI 行为段覆盖率 ≈100%。覆盖不了的行为段
= 词汇缺口 → 进入补词清单（不经 RL 自学）。**反向完备性断言（P0-1）**：God-AI 每个非 reflex
细分支必须在 ≥1 个意图白名单内可达——静态表即可先抓，省一轮 M7 返工。

### 3.4 锚点契约（I3，M0 交付物，实施前定稿）

- **role = 实例级槽位（P1-1 钉死）**：目标锚头输出 **16 个 role logits**（如 base-guard×4 / mid-lane×3 / spawn-lane×2 / retreat-anchor×3 / reserve×4，M0 定案），**每个 role 在本关解析出唯一坐标**（关卡加载时校验唯一性）——禁止"1 role 多实例"歧义（实例挑选规则若需要，必须预注册并镜像进 tagger）；
- 执行器在**关卡加载时**把 role → 本关坐标解析（每关锚点库 = role×坐标表，入执行器库）；
- 标签来源：tagger 选定锚点时记录 `anchorRoleId`（角色 id，**不是关内序号**——朴素"anchorId 仅关内有效"方案会使 BC 跨关泛化失效，弃用）；
- 网络输出解释 = role logits → 推理时由执行器查本关 role 坐标表；
- **解析器统一注册表 = 聚合封装现有实现**（`computeBaseGuardAnchorImpl` [StrategyPlanner.ts](file:///d:/github/battle2/src/ai/god/StrategyPlanner.ts)、`getDefaultDefensePositionImpl`、think.ts 站台内联、`findLaneDefensePointImpl` [PathCarve.ts](file:///d:/github/battle2/src/ai/god/PathCarve.ts) 等）——**不新造轮子**；各缓存/reset 失效语义必须原样保留（确定性），工作量在 M0/M6 报实际数。
- **逐关解析报表与确定性回退（Q4）**：M0 产出 35 关 × 16 role 的「0/1/多解析」表——**多解析或不可解析的 role 用确定性回退规则**（就近可用 / 最近安全格，写死进执行器库），回退规则**镜像进 tagger**（标签-执行一致）；M4 报"依赖回退的关数占比"，M6 加**锚点失效测试**（role 目标格被占/被毁时执行器行为 = fallback 至 INTERCEPT/撤退，禁止站死）。

### 3.5 父意图→激活头矩阵（P0-4，进 M0 标签契约）

8×2 的 0/1 表（M0 定稿；草案示意：enemy 头激活 ⊆ {INTERCEPT, HUNT}；anchor 头激活 ⊆ {RETURN-DEFENSE, HOLD-LANE, CRUISE}；PICKUP/CLEAR/ESCAPE 的目标由执行器规则决定、不解释任何头）：
- **训练**：非激活头损失权重置 0——不产梯度、不计 acc、不喂占位标签；
- **推理**：仅当意图头选中某类后才解释其激活头；执行器契约写明"未激活头输出必须忽略"；
- 该表同时约束 tagger（God-AI）与签名器（人像）——两 oracle 口径一致，是 M6 一致性复测（I7）的前置。

**目标敌头槽序（P0-1 修正，M0a 钉死）**：原预注册 #2"沿用 schema v2 obs-encoder 敌方通道槽序"**引用对象不存在**（encoder 只有 4 个按种类分的空间敌通道 + nearestEnemy 三标量，无 e0..e3 槽序）。槽序**新定义为 obs 可计算的确定性空间函数**：**距基地升序，tie-break 行主扫描序**（敌格位置与基地格都在通道网格里，网络可自行推出——注意：评审建议的"killSlack 升序"不可采纳，encoder 只输出 min-slack 标量、无逐敌排序信息）；tagger/executor 共享同一实现模块（禁两份）；M0b 探针**增报目标敌头 acc vs 多数基线余量**（槽序不可学会在第二个头上撞出"表达墙"假象，污染 Q1 判读）。

### 3.6 意图可学习性前置探针（Q1，M0 gate 附加件——全案第一前提的巷口检验）

在投入执行器/训练管线之前，用**临时的规则版标签器**（= M0 的 19→8 映射直接用 `ACTION_WEIGHTS` 机械实现，
一次性、不进正式 tagger；**标签源 = runChain commit 的候选 id（P2k3-2）**——与 M1 真 tagger 的
StrategyPlanner 内部模式存在口径差，该差值正是 M6 I7 一致性复测的对象）**全 2100 局重跑逐 tick 打标**
（P1-5k3：npy 现有 shard 是采样决策帧、不含逐 tick——去抖/转移边界只能在逐 tick 流上做），然后：

1. 训纯 intent-8 head 分类器（复用 StudentNet 主干，**无 prev-intent 注入**），按 divergence-probe 三桶报告
   **acc vs majority 基线余量**；**任何桶余量 < 0.1 → 表达/时序缺口嫌疑升级，先改词表或补 obs（时间堆叠），
   不许进入执行器投入**（Q1 门槛，预注册 #16）；
2. 产出**类分布幽灵表**（8 类窗口计数，Q10：预计 CRUISE/HUNT/INTERCEPT 占大头——确保 M5 前看清
   多数类下采样与配额参数，而非撞上样本瓶颈才改）。**双口径（P1-5k3，预注册 #28）**：自然分布（全 2100 局）
   与训练构成（wins+near-miss 3×）各一张；**<200 窗口裁决用自然分布表**——训练构成下 ESCAPE 会被守家类
   超采样污染；
3. 产出**时序变化指标**（Q1）：同帧前后 ±5 tick 意图翻转比例——显著偏高 = 时序表达缺口的直接暴露；
4. **失败处置五径（P1-2/P2k3-3）**：余量 <0.1 时按序处置——**①改分段/去抖规则（最便宜最可能）→ 重跑探针** →
   **①.5 注入版探针**（prev-intent teacher-forced：区分"状态表达缺口"与"缺时序上下文"，比 schema v3
   便宜一个数量级）→ ②改词表 → ③补 obs 时间堆叠（= schema v3 bump，bump 前先出重导成本评估）；
   **探针重试上限 3 轮**（仍败才升级到 schema bump）；翻转阈值量化（±5 tick 内标签不同帧占比 >X% 判时序缺口，
   X 预注册 #23）。

## 4. 网络选型与参数规模（已定案）

**复用 StudentNet 主干（CoordConv-ConvMixer，BN-free，≈67.5K——schema v2 现行实算，[student_model.py](file:///d:/github/battle2/nn-training/student_model.py)；"68.7K"是 v1 三头旧口径，引用时标注版本）+ 三头**。主干可迁移初始化（复用 v2 纪元现训的 move/fire BC 权重的主干，头重新初始化）。**不发明新网络**；拒绝纯 MLP（手工特征=重造感知层）与 RNN/Transformer（TS 确定性成本高；意图记忆用注入特征解决）。

**迁移初始化双臂（P1-3）**：主干初始化跑 random vs transfer 双臂（挂在 A 臂数据上，2 次训练成本买干净结论）。前提校正：transfer 来源 = bc-b/dagger 系列权重，**schema v2 原生训练、与意图网同纪元，连续性成立**——不确定性的真正来源是"0% WIN 模型的感知特征是否利于意图任务"，而非版本断裂；止损线：5ep 内 transfer 无 acc 优势即弃用迁移（入预注册 #12）。

### 4.1 各层参数（草案）

| 层 | 尺寸 | 参数 |
|---|---|---|
| CoordConv 注入 | +2 通道（坐标，进 stem） | 0 |
| stem conv | 16→64, 3×3 | 9,280 |
| ConvMixer ×8 | dw 5×5 + pw 1×1（h=64） | 46,592 |
| GAP + scalar 融合 | (64+19)→128 FC | 10,752 |
| ① 意图头 | 137→8（含注入 9 维） | 1,104 |
| ② 目标敌头 | 137→5 | 690 |
| ③ 目标锚头 | 137→16 | 2,208 |
| value 头（M8 启用） | 137→1 | 138（P2k3-6） |
| **合计** | | **≈70.6K** |

**注入位置已钉死（I1）**：意图状态 9 维（one-hot 8 + 持续时长 1）**拼接到 FC 输出的 128 隐藏向量之后**（128→137 进三头），**不触碰 stem 与 FC 输入维**——主干 + FC 权重可原样迁移自既有 StudentNet，仅三头与 concat 层需初始化。配套断言（预注册 #8）：导出权重时校验 stem/ConvMixer/FC 的 shape 与既有 StudentNet **完全一致**。

瘦身备选 h=48/d=6 ≈ 40K（仅当标签量证明不需要全场细粒度时启用）。

### 4.2 运行时注入（零 schema 成本，位置已钉死）

`当前意图 one-hot(8) + 意图持续时长(1)` = 9 维，**拼接在 FC 输出的 128 隐藏向量之后**（§4.1 已按此计参）。先例 = student_model.py 的 CoordConv 坐标通道：不在 schema 内、在 forward 生成——**不做 OBS_SCHEMA_MAJOR bump**。这是网络学"承诺/粘性"（§169/§170 想补的）的输入；运行时由 IntentPlayer 策略层维护并注入（本次决策使用上一决策窗口的意图与时长）。

### 4.3 推理预算（P0-1 修正：实测口径，非理论估算）

- **单次前向 ≈34–56 ms（Q8：为估计区间，非实测）**：37M MAdds ÷ 吞吐基线（Bun JSC 桌面 1.1G MAC/s 为 **BC 实测**；depthwise 5×5 折扣 **0.6× 为估计系数** → ≈0.66G，[RL-Net-Selection.md:82-90](file:///d:/github/battle2/plan/RL-Net-Selection.md#L82-L90)）。**M4 用意图网真实三头权重 bench-nn-infer 实测落档为准**；obs encode 占比 <1% 一并写入；
- **摊销**：÷ replan=24 → ≈1.4–2.3 ms/tick；÷ replan=50 → ≈0.7–1.1 ms/tick；
- **单次延迟超 16.7ms 帧** → 实机每 replan 一次可见卡顿；headless（m1-eval）不受影响。实机部署 = 另立决策（Worker 卸载 / 降档 h=48≈25M）——与现状 NNInput K=10 同题（[policy-input.ts:146](file:///d:/github/battle2/src/nn/policy-input.ts#L146) 同步阻塞）；
- **M4 gate**：`tools/bench-nn-infer.ts` 实测三头权重**单次前向 ms 落档 + 摊销 ms/tick 计算**（预注册这两个数字为基准，不再用"≤1ms"字样）；
- 瘦身档启用条件扩为："标签量证明" **或** "实机帧预算证明需要"（P0-1）。

## 5. 标签体系

### 5.1 God-AI tagger（教师标签）

- 在 `src/ai/god/think.ts` 加意图日志支路（**无侵入，P1-6**）：零 `world.rng` 消费、零决策路径改动；每 replan 决策 tick 输出 `(intentId, targetEnemySlot, anchorRoleId)` + 注入特征（prev-intent/duration）落盘；
- think.ts 内部状态映射到 8 类词表（M0 定映射表——StrategyPlanner 模式 → 主类的归属是 M0 交付物，不是临场定）；
- **意图分段规则四件套（P0-2，预注册 #19——标签体系最核心规格，禁止临场）**：①**去抖**：候选连续提交 ≥N tick（N 预注册，建议 3–5）才构成稳定意图段；②**reflex 透明**：dodge/survive 类候选不打断分段，其帧标签 = 当前活跃意图（与 Q10 的 ESCAPE/reflex 分工口径对齐）；③**短段处置**：稳定但 <N tick 的段归前段/后段/单列——预注册；④**探针同步**：§3.6 机械 tagger 必须实现同一分段规则（含 N 值），否则探针测的不是最终标签函数的可学习性。
- **采样方案（P0-3，转移包含式，已定案）**：标签集合 = 均匀 replan 网格 **∪ 全部意图转移边界帧**（tagger 每 tick 都在跑，转移事件免费获取）——短窗口类（ESCAPE/PICKUP）不被固定网格饿死；边界帧的注入特征同步落盘；
- **标签契约含 §3.5 激活头矩阵**：非激活头不产标签；
- **tagger ON vs OFF 同 seed 全局逐字节一致**：两条断言进 CI（(a) tagger ON/OFF 等价；(b) IntentPlayer 推理 argmax 确定、不消耗 world.rng）；注入状态只存在于 InputLike 实例、`reset()` 清空（NNInput 先例），不进 World；
- **语料口径（P2-3，M0 拍板）**：默认沿用 wins + near-miss 3×（意图监督更稀疏、守家黄金段含败局防守成功片段——M0 一句话记录理由，不留白给临场裁量）；**tagger 是"全轨迹确定性函数"而非单帧纯函数（P1-6k3 措辞收紧）**——依赖 GodAIInput 内部态（navCache/commit/_lastBranch），学生 rollout 打标需逐 replan 状态**冷启动实例化 GodAIInput 问价**（export-dagger-labels.ts 先例，可行但不免费）；⇒ 旧 replay 可重打意图标签（扩料通道，M0 评估是否启用）。

### 5.2 人类行为签名标签器（保住第二 oracle）

- **禁止用 God-AI 意图分类器给人类帧打伪标签**——那会把人类录像降级为"状态分布增强"，丢失第二 oracle
  （且人类玩得比 God-AI 好的状态会被教歪）。
- 签名映射器 = 纯函数，从运动/火力/与基地敌人的位置关系反推意图。8 类每类 2–3 条判据（先例草案：
  位移主向指向基地+火力断→RETURN-DEFENSE；走廊小幅摆动+朝敌来路→HOLD-LANE；朝向最近敌+开火→HUNT；
  面向墙持续开火→CLEAR）。签名判据 = 执行器语义的镜像，两者同源。
- 底线：某类签名判据模糊 → 该类**宁缺勿错**（宁可少标，不喂错误意图标签——意图级错标比 move 级更毒，
  一个错 defend 教坏整个窗口）。
- **每类窗口绝对计数表入 M2 报告（P0-3/P1-4）**：下限 **≥200 窗口**才算该类可学；低于下限的类自动进入"宁缺勿错"处置；训练采用**每类配额采样**（P2-2，沿用 near-miss 3× 先例），参数入预注册 #13。
- **oracle 增益量化（Q3，操作化定义 P0-4/P0-2k3，B 臂的支柱验证）**：在人像轨迹的意图分歧帧上，通过
  **`orderedCandidates` 候选强制提交**（[think.ts:3256](file:///d:/github/battle2/src/ai/god/think.ts#L3256) /
  [DecisionCore.ts:216](file:///d:/github/battle2/src/ai/god/DecisionCore.ts#L216)，已核实存在）执行互换意图，
  短窗重放比 baseIntegrity/击杀后果。**强制提交的静默失败模式（P0-2k3，已核实 `evaluate()` 只在 entry 谓词
  满足时才 commit，[DecisionCore.ts:174-183](file:///d:/github/battle2/src/ai/god/DecisionCore.ts#L174-L183)）**：
  人像状态对 God-AI 候选是 off-manifold，大量互换无法 commit——**必须上报「可强制率」+ 不可强制帧桶分布，
  B≤A 判据只在可强制帧上计算**；不可强制帧处置三选一预注册（跳过 / 降级至同白名单内最近可 commit 候选 /
  bypass entry 注入动作——建议中间档），预注册 #24。**近似口径必须写明**：分歧帧上的 God-AI 是**冷启动决策**
  （其 navCache/commit 内部态在人像轨迹上不存在，冷启动 ≠ 流内决策）——M6 后用真执行器复核存疑桶。
  **判 B≤A → 触发 §1 降级分支（写死）**；
- **B 臂混杂因子控制（P1-4）**：①**B′ 平滑对照臂** = A 标签做窗口多数平滑后训练（排除"签名标签更平滑
  所以更易学"的替代解释；B ≈ B′ ⇒ 增益归因存疑）；②**B/A 窗口比例量化**：B ≥ 30%×A 总窗数（每类 ≥200
  已有），预注册 #20；③**B 臂 init 双臂**（random + transfer 同跑，4 次训练总量可控）。
- 人像 97 局全部为"基地存活"正例 = 基地高压桶的黄金正样本（M1 证明该桶是全案主分歧区）。

## 6. 目标层（RL 奖励，若进入 RL 阶段）

- **意图作用域窗口奖励**：每个意图窗口独立结算（hunt→+击杀；intercept→−目标入环时长/+拦截击杀；

  per-tick 即时、语义对齐、梯度短。**按模式配置化**（死斗/塔防各一张表，config 不是代码）。
  **类间量纲平衡（P2-7）**：HUNT 击杀密集 vs RETURN-DEFENSE 防守稀疏 → PPO 必然偏 dense 类；M0 奖励表
  按类**量纲平衡并预注册**；M8 报告加"意图类选择分布 vs God-AI 分布"对照（偏斜即报警）。
- **切换成本项**：无产出切换 → 负分（治意图摇摆，配合注入的"意图时长"特征形成可学承诺）。
- v7 教训在案：dense 分量存在（击杀即时），但 baseSafety 饱和零梯度 → 新 reward 表必须对
  "敌人逼近基地"给**非饱和即时梯度**。**落具体设计（P2-5）**：基于 nearest-threat-distance 的
  potential-based shaping（按格分档），写进预注册 #5 奖励表——避免重演 v7"分量存在但饱和"。
- 基地防守追踪线：baseIntegrity + 距 God-AI 地板（76%）差值，每 iter 必报（延续旧计划 Q5 纪律）。

**RL 算法与 semi-MDP 假设（I13，M8 前定案）**：算法 = **PPO**（复用 `ppo.py` 与 `PPOStudent.value_head`）；
决策只在 replan tick 发生、窗口内动作冻结；奖励按意图窗口累计，GAE 在**意图步**上计算（每局 ≈100–300 步，
非逐 tick）；**value 头与三头并列消费同一 137 隐藏（128+9 注入，P1-5②）**——value 必须看到承诺状态，
否则同 obs 不同意图龄的 value 估计系统性偏差。**意图步 γ 口径（P1-5③）**：per-intent-step 取
**γ_step = γ_tick^Δt**（Δt = 窗口时长，可变），与现有 per-tick γ=0.995（returns 导出、rl-reward.ts）
换算一致——否则 M8 的 returns 与 BC 期 value 预置数据不可比（预注册 #21）。

**评估协议与止损（P2-5/P1-1k3）**：M8 主指标 = **Δ vs M7② 基线的配对干净评估差**（冻结权重 + argmax + 固定
EVAL_SEEDS，[DECISIONS §245](file:///d:/github/battle2/DECISIONS.md#L1636) 协议），绝对胜率退居参考；
**k3-P1-1 修正：§245 的 EVAL_SEEDS 仅 2 seeds × 35 = 70 局（单点 SE≈5.5pp）撑不起 iter15 数 pp 级判定——
iter15 gate 改用 350 局（m1-eval 默认 10 seeds × 35），pace 数值按 350 局 SE 重标（预注册 #27）**；
**中途止损**：iter15 时 Δ≤0 或 baseIntegrity 无上行 → 转 M9（词表增长），不续命；
**M8 超越论证显式化（P2k3-10）**：PPO 在 15–25 iter 贡献若干 pp 的依据 = 起点 ≥50% + 动作空间仅 8 类 +
窗口密奖励 + horizon ~100–300 步（对比旧谱系全动作空间 68it 平台 ≈10%）；**零成本先行指标 = M7① 四档
cadence 的 WIN 方差（达数 pp 即"切换时机有优化余量"的直接证据）**。

## 12. 后继努力方向（intent NN 完成/封顶后，2026-08-27 用户确立）

> 来源：用户实机观看 intent NN 录像后确立。这些方向**不属于** M8/M9 当前阶段交付，
> 是意图方案抵达天花板之后的下一步候选。执行任何一项前须重读本文件 §0 与
> DECISIONS.md 的阴性归档，防止重蹈"局部改善、全局翻车"。

### 12.1 已观察的实施层缺陷（intent NN 与 God-AI 共有，非意图选择层问题）

用户观看 intent NN 录像发现三类行为缺陷，均落在**执行器实施层**（意图选定后怎么走/打/拆），
不是意图选择层——**NN 训练（意图头）无法直接修复**；且 move/fire 层级学习已被四项证据
判死（§0），"从人类学实施层"是死路。

| # | 缺陷 | 根因分析 | 可表达性（if-else） |
|---|---|---|---|
| 1 | 冰冻道具起效期间在不同目标间摇摆 | 目标切换无承诺：每 tick 重新评估最近敌，谁近打谁 | 可表达——重评 §170 `huntCommitTicks`（目标黏性，M0 列"5 项立项未测"），+ 意图→执行器调制标记（suicideReturn 压制 dodge 先例） |
| 2 | 不会清墙开路 | 双重缺：NN 极少选 CLEAR（it26-32 仅 0.4-3%）+ 执行器无"顺路清墙"overlay | 可表达——overlay 层"前方挡路且无威胁→拆一炮"，纯 if-else，契约已预留 |
| 3 | 追击走并行车道横向开火，不并入目标车道后方 | 执行器缺"追尾导航"子分支：路径目标=目标位置而非目标**后方 1-2 格** | 可表达（导航层子分支），难度中等，难在并道避让 |

### 12.2 归档禁用项 = 改进的对照基线（不可轻易重开）

DECISIONS §166（starRush）等 **20+ 项实测阴性**（starRush / coverage 五轮 / 中路初版 /
§81 逐关名覆盖表等）保持**归档不重开**。它们证明：局部改善 + 全局翻车是这条规则链的真实
风险。因此 §12.1 的任一修补**必须**遵守：
- 先写行为级测试证明只在目标意图窗口触发、不污染其它意图；
- 60-seed 全关卡净收益门（局部提升不算数）；既往阴性项在改动后逐项复查未被重新激活；
- A/B 账本准入，可一键关停；意图窗口收益核算（窗口内提升 + 无窗口外回归才放行）。

### 12.3 无监督学习路径（用户设计意图）

用户开启 per-tick RL 的初衷 = 期望通过**无监督学习**克服实施层缺陷。诚实标注与 §0 的张力：
§0 判死的是"从零 RL 学 move/fire"（旧谱系全动作空间 68it 平台 ≈10%）；用户意图是在
**意图框架约束下**以无监督方式优化实施层（层级混合：NN 选意图 + 无监督微调执行细节），
二者不是同一件事。该意图**列为"假设待验证"**，进入任何后继执行前须先做可行性评估
（动作空间收窄到意图内子分支、奖励如何给实施层、与 §2.3 确定性/One Author 的兼容），
不因用户期望而默认成立。

### 12.4 反哺通道（NN → 规则）

intent NN 若达 82% 量级，其价值不止于部署：意图分布/切换时机/目标偏好可作为
God-AI config 微调（差异桶取证）与执行器库扩充（NN 探索出的新行为固化成子分支）的
教师信号。预期规则侧上限 ≈ 表达自由度（~77-78%），完整复刻 82% 不现实——反哺定位为
"让可部署体更实用 + 让 NN 行为可解释"，而非"让规则也 82%"。

### 12.5 意图条件化 action NN（层级实施层学习，2026-08-27 用户确立）

**设想**：在 intent NN 基础上再训一个**更小规模的独立 action NN**，专门控制既定意图内的
移动/开火，克服 §12.1 实施层缺陷（目标摇摆/清墙/追尾）。

**与历史死因的关系（为何方向值得）**：§0 判死 move/fire 学习的死因有二，本方案各绕开一条——
- BC 死因（监督级联）：action NN 走**无监督 RL**（on-policy 自采），不存在逐帧教师标签级联；
- 旧谱系 RL ≈10% 平台：动作空间**条件在意图上**（P(action | state, intent)），动作子集小、
  语义聚焦，奖励不再跨 5 动作打架。文献上 = option / hierarchical 学习，方向有真实依据。

**四道硬门槛（执行前必须逐条回答）**：
1. **执行层 per-tick 奖励怎么给**（成败关键）：命中率/被弹率类宏观量 → 梯度稀疏；v7 教训
   （饱和零梯度）在案。需为某缺陷设计**非饱和即时梯度**（如追尾方位角 + 命中事件）。
2. **与 God-AI 执行器的边界**：全接管（删执行器，重构大）vs 只补缺（仲裁复杂，回归 §12.2
   风险）。至少前期用后者、并限**单一意图窗口**内验证。
3. **推理预算**：intent 前向已 41ms（R3），再叠加 action 前向 → 实机震颤；headless 不受限。
4. **隔离纪律**：只影响选定意图，不污染其它；走 §12.2 对照基线（60-seed 净收益 + 阴性复查）。

**最小验证探针（建议路径）**：挑最可量化的缺陷（追尾导航：玩家相对目标方位角 + 命中），
action NN **只在 HUNT 意图内**接管走位/开火，其余意图仍走 God-AI。判据：HUNT 窗口命中/击杀
效率显著优于执行器 → 方向成立再扩全意图；学不动（奖励给不上或无净收益）→ 归档，成本仅
几次训练。探针一次性回答"执行层 per-tick 奖励给不给得出梯度"这个子问题。

**与 §12.3 的关系**：12.3 是"意图框架约束下无监督微调实施层"的**泛方向**；本节是其**最具体
落地形态**（意图条件化 + 单意图验证）。探针结果同时检验 12.3 的可行性假设。

### 12.6 人类手打录像的利用通路（SFT / 先验，2026-08-27 用户质询）

**现状盘点**：104 局人像（97 胜、覆盖 s1-31、每关 3-5 局；s32-35 零覆盖）已双层封存
（ndjson + obs v2 快照 97 shards/65,513 样本 + 签名标签层 nn-demo/seal-premerge）。
用途现状：仅经 M2 签名标签器 → B′ 臂（意图层混合，已验证 +1-2pp）。

**分层判定（SFT 的两种打开方式）**：
- **意图层 SFT = 已做过且有效**（B′），剩余增益 = 补 s32-35 人像（当前 0 覆盖，恰是
  God-AI/NN 最弱 4 关）+ 每关增量。属**标签稀缺**问题，非方法问题；65,513 样本够小步微调
  或混合采样，不够纯 SFT 全量训练。
- **执行层逐帧 SFT = 历史死路重走**：move/fire 恒等监督 = BC 死因（监督级联），禁。
- **正确形态 = 人类作为 RL 先验/自举，而非监督目标**：人类执行轨迹 → 提取"状态→移动/开火"
  建议分布 → 作 action NN（§12.5）的（a）初始化先验（BC warm 数轮做探索起点，再 RL 优化，
  标准 imitate-then-RL 混合）或（b）KL 约束锚点（防 RL 跑飞）。人类守家窗口轨迹另作 RL
  数据增强（差异桶采样）。

**风险（B 臂前车之鉴）**：人像分布窄（s1-31、风格单一）+ 全胜正例 → 微调过头退化
（B 臂 quota 4000 塌向 RETURN_DEFENSE 的实证）；需保持温和混合比 + 自然分布验证口径。

### 13.1 逐项理由

**P1 — 三缺陷修补，按序逐个过 60-seed 门**：
- 顺序：① 冰冻期目标承诺（重评 §170 huntCommitTicks，最便宜最隔离）→ ② 顺路清墙
  overlay（三层契约已预留，纯 overlay 天然不污染）→ ③ 追尾导航（最难，并道避让）。
- 这是**唯一同时抬 God-AI、oracle、NN 三方天花板的方向**——oracle 76.6% 是含三缺陷的
  成绩（§25），三缺陷修掉前任何策略到不了 78%。且修的是可部署体，不依赖 NN 存活。
- 风险实事求是：阴性基率高，但 §169–173 当年是"立项未测"，且在"选择器+承诺期"架构下
  可能翻案——用现成的净收益门逐个裁定，翻一个归档一个。

**P2 — HUNT 追尾 action-NN 探针**：唯一可能**学出 if-else 表达不了的行为**的方向，一次
回答两件事：§12.3 可行性假设 + 实施层 per-tick 奖励给不给得出梯度。成本 = 一个小网 +
几次训练。与 P1-③ 天然互补：P1-③ 被门杀 → P2 兜底；P1-③ 过门 → P2 回答"学习 vs 手写的
天花板差"。注意推理预算只影响实机，headless 评估不受限。

**P3 — 人像补料**：最便宜的直收方向——补打 s32–35（4 关 × 2–3 局）+ 复用 B′ 管线，恰打
在 it38 最弱桶上；B′ 已验证守家信号 +1-2pp。执行层逐帧 SFT 已判死，禁踩。**前置依赖**：
等 P0 取证。若 s34 是选择质量问题 → 直接获益；若是执行器天花板 → 补料也白搭，得先等
P1/P2 抬顶。

**P4 — 反哺通道，暂缓**：前提是 NN 明显优于规则侧、差异桶里有可固化映射。事实是 it38
75.0% vs God-AI 74.3%（同 m1-eval 口径）落在噪声带内，"82%"没有任何实证落档。无教师信号
的反哺是空转。**若 P0 复现中真出现 82% 口径 → 立即升到 P1 档**（可部署 +2~5pp）。

**P5 — M9，除非取证挖到真缺口否则不开**：覆盖 ≈100%、无在案缺口、新词无执行器新行为 =
空词，大概率 Q9 三连停。降级为 P1/P2 成功后的取证驱动跟随项。
