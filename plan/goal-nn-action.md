## 1. 背景与决策依据

### 1.1 已证伪的前提

手册隐含假设"执行器 + 好目标 ≈ 竞争力下限"。T9a 用 2100 局配对评估证伪了它：

| 配置 | 胜率 | 场均击杀 | 数字是否可信 |
|---|---|---|---|
| God-AI 基线（pinned） | **78.81%** | 18.18 | ✅ `reports/godai-baseline-hard-35x60` |
| `--policy goal`（网络 + 独立执行器） | 0.05%（1/2100） | 2.13 | ❌ 报告 17:10 < 冻结修复 `b84c012`（17:37） |
| `--policy goal-god`（God 目标 + 独立执行器） | 0.0% | 1.29 | ❌ 探针失真（见下） |

**两个数字都不能进账本**（同类坑的第三次，前两次：新 policy 静默回退成 God-AI、规格矛盾冻住坦克）：

- `goal`：那一跑坦克还会被规格 bug 冻在原地（`travelEst ≤ T` 移动拴绳）。
- `goal-god`：目标在心跳处快照后**持有 ≤240 tick**（God-AI 每帧都在改主意），且
  `_navCacheValid=false` 时回退成"朝当前朝向 +4 格"的幻影点。**硬证据**：它的场均击杀
  1.29 **低于** BC/PPO 网络的 2.9 —— 一个"完美目标"不该比学出来的差。

⇒ 结论"执行器是瓶颈"**方向成立**，但两个支撑数字都需重测（卡 A0/A4b 承担）。

### 1.2 历史阴性证据，以及课程学习如何拆掉它们

| 尝试 | 结果 | 当时同时成立的不利条件 |
|---|---|---|
| IL/DAgger（逐 tick 模仿 God-AI 的 move/fire） | 学生 **0% 胜率**（God-AI 75%） | ① 真实关卡、状态分布极宽 ② 教师分布外无标号 ③ 无自身奖励 |
| RL（`run_rl.py`，68 iters / 38.5h） | it1 即未见收敛 | ① 真实 stage 0–3 / 12000 tick ② 守家向 Φ 奖励 ③ 从那个 0% 胜率的 BC 权重起步 |

**课程学习同时拆掉这三条**：玩具场压窄状态分布（模仿学得动）、击杀/生存奖励稠密
（不用等 12000 tick）、回合短（同墙钟多跑两个数量级样本）。这不是"再试一次运气"。

⚠️ 但"回合短"这个前提**必须由 A1 逐级钉死**（§2.3），否则默认回落 `--max-ticks 12000`。

### 1.3 为什么不蒸馏 God-AI

模仿学习的天花板在构造上就是教师本身 ⇒ 蒸馏 78.81% 的 God-AI 出不了更高。
本方案中 **God-AI 只当 warm start（定起点），RL 自己的奖励才是天花板（定终点）**，
并由卡 A5 的同预算消融显式检验（§3.7）。

### 1.4 目标与非目标

**目标**：一个**决策独立**的逐决策步执行器（move/fire 由网络产出，不经 God-AI 候选链仲裁），
在 hard 35 关上**不劣于 78.81%**，并在此之上重新获得"目标轴是否有价值"的可测条件。

> ⚠️ **"独立"的精确含义**：是**决策独立性**，**架构上仍与反射层共存**。
> 部署态是否还跑 God-AI 链取决于 §3.5 选 (e) 还是 (c)：(e) 不跑；(c) 仍要跑以产出 `_lastBranch`，
> 且推理成本须计入 God-AI 前向。A5 消融的结论范围只覆盖 move/fire 两头。

**非目标**：不删/不旁路/不改 God-AI 候选链与 `ACTION_WEIGHTS`；不改现有 difficulty 行与 35 关；
本阶段不做上机部署（T11/T12 冻结）；不改 obs schema（§3.2）。

### 2.3 三条环境侧陷阱

**(a) 单地图过拟合**（三轮评审都没抓到的一条）。`makeArena` / `makeMazeStage` 是**无 RNG 的纯函数**
（`curriculum.ts:55-138` 无 `rng`/`random`），布局由 `(size, enemyCount, base)` 完全决定，
spawn 与 `enemyKinds` 每场固定 ⇒ **有 agent 级随机性、无地图级随机性**。
每级只有一张图，智能体**背图**就能刷高指标 —— 相对 + 绝对双轨门挡得住刷分、**挡不住背图**。
⇒ 加 `layoutSeed`，**每级 3 张布局变异（写死 3，不许中途加）**，A0 在同样 3 张上锚定并报变异间方差。

**(b) 敌种通道的暴露梯度**。真实梯度不是"全零直到 S4b"：

| 级 | ch7 basic | ch8 fast | ch9 power | ch10 armor |
|---|---|---|---|---|
| S1 / S2 | ✅ | S2 已加料 ✅ / S1 ❌ 恒 0 | ❌ 恒 0 | ❌ 恒 0 |
| S3 / S4a（= `STAGES[0]`） | ✅ | ✅ **仅 2 个** | ❌ 恒 0 | ❌ 恒 0 |
| S4b（真实 35 关） | ✅ | ✅ | ✅ | ✅ |

⇒ ① S2 直接用现成的 `enemyKinds:['basic','fast']` 激活 ch8（**不新增 S3.5 级**，避免再拉长梯子）；
② ⚠️ **减半敌人必须分层抽样，不能截断队列前 N 个** —— `ENEMY_FORCES[0] = 'aaaaaaaaaaaaaaaaaabb'`
（`stageData.ts:535`）的 2 个 `fast` 在**队尾**，截断会把它们切光，S3 反而退化成纯 basic。

**(c) 训练 `--max-ticks` 必须逐级钉死**。`run_rl.py:227` 默认 **12000**、
`export-rl-rollout.ts:62` `MAX_TICKS=36000`。若智能体学出"苟活不杀人"（§3.4 明确要防的刷分形态），
一局就是 12000 tick ⇒ 短回合前提坍缩、shard 体积与 return 折扣时域（γ=0.995 @K=10 ≈ 33s 语义，
12000 tick ≈ 200s）全部变形。⇒ A1 逐级钉死（初值 S1/S2 = **1200**，S3/S4a 按 A0 的 ticks 分布定）。

### 2.4 锚定规则（相对门的基准怎么定）

- **门是相对的**：阈值锚在 A0 量出的 God-AI 同场数字上，不是拍脑袋的绝对值。
- **必须配绝对下限**（防"锚有效性"问题）：God-AI 是为有基地、攻防切换调参的，在无基地玩具场上
  可能本就次优 ⇒ 若锚本身很弱，"≥ 锚值 80%"会是很低的天花板。**绝对口径不依赖 God-AI**，
  直接以任务完成度定义（见 §2.1 表中"绝对"行）。
- **锚稳定性兜底**：A0 每场报 **seed 间方差 + 变异间方差 + God-AI 通关率**。
  **通关 <60% 的场 ⇒ 锚不可用**，该级改用绝对阈值，**数值在 A0 报告里当场定死**（防事后挪门）。
  已知风险证据：`curriculum.ts` stage 4 需 pin `aimError=0` 才能过、stage 3 换 seed 曾翻转。
- **S3 备选场**：`makeMazeStage` 直接复用 `STAGES[0]` 全套（20 敌），从 S2 的 3 敌跳到 20 敌。
  A0 须给出减半敌人的备选场；若 S3 锚退化则换场（**在 A0 报告里预注册，不许中途换**）。

## 3. 系统规格（怎么训）

### 3.1 动作空间（沿用现成，不改）

`nn-training/rl_model.py` 已是 **ResNet 双头 `[move(5), fire(2)]`**（v2 已删 item 头）。
控制间隔沿用 `export-rl-rollout` 现有窗口（**K=10**，`export-rl-rollout.ts:63`；实现时核对并记进日志）。
需要更细粒度另立卡。

**捡道具不需要动作头**：若道具为经典规则（触碰即拾取），它就是纯移动行为。A7 内用一局回放确认；
若需按键拾取，再单独立项。

### 3.2 观测（不许改 shape，但必须修语义）

沿用 `obs (N,14,26,26) u1 + scalars (N,19) f4 + mask (N,7) u1`。
arena 与真实关卡**必须同构**，否则每级升级都要重训主干、迁移失效。

> ⚠️ **别信注释，信代码**：`export-rl-rollout.ts:32` 的注释写 `scalars (N,24)` / `mask (N,10)`，
> 都是 v2 删 item 头之前的旧值。真实值见 `schema.py:22`（`SCALAR_DIM=19`）与
> `schema.py:27`（`MASK_DIM = MOVE_DIM+FIRE_DIM = 7`，导出器 `:607,629`）。
>
> ⚠️ **mask 是 u1 硬掩码，不是软偏置**：应用处 `mask[i] !== 1 ? -1e9 : logits[i]`
> （`:296,302`）⇒ 只能"**禁止**"动作，**无法"鼓励"**动作。这决定了 §3.6 方案 1 的边界。
>
> ⚠️ **通道已占满**：14 个 obs 通道（`schema.py:34-49`）与 19 个 scalars（`schema.py:57-77`）
> **均无空位、无保留维** ⇒ 任何"加一路目标输入"都必然改 shape、触发止损线 4。

**幻影基地（必须修）**：`obs-encoder.ts:184` 无条件写鹰 `isBaseDestroyed() ? 0 : 2`，
而 `TileMap.ts:227-230` 的 guard 明说"无基地不算被摧毁" ⇒ 无基地 arena 上 **ch5 每帧在
`BASE_POS`（行 24–25 / 列 12–13）画一尊不存在的鹰**；ring 因 arena 外围钢填充恒为 1；
`s1 / s6 / s17 / s18` 等 base 标量全是幽灵值。整条梯子会把它们训成"常量、可忽略"，
到 S4a 出现真基地时突然变成生死信号 —— 而这在"不动 obs"的红线**之内**，止损线 4 拦不住。
⇒ **A0a 修**：`tileMap.hasBase() === false` ⇒ ch5 全 0（不改 shape）。God-AI 侧早有同类保护
（`GodAIInput.ts:213-218` 的 `hasBase` 缓存），RL 侧没落地。

### 3.3 网络与权重迁移

沿用 `rl_model.py` 现成网络。**每级升级 obs/动作/网络形状全同 ⇒ 权重整份迁移**，只换环境
（比手册 §T9a.2 的主干 warm start 更简单，那里还要换热图头形状）。**这条是迁移卖点，
任何改动形状的需求都触发止损线 4。**

### 3.4 奖励

**玩具 scheme（S1–S3，卡 A2）**：

```
R = w_kill·击杀 + w_hit·命中 − w_dmg·被命中 − w_death·阵亡 + w_alive·存活（每步小常数）
终局：全歼 +w_clear，阵亡 −w_death
```

- 不得污染 `rl-reward.ts` 现有常量（其 Φ 全是基地压力口径，在无基地场无意义）。
- **预注册三组权重扫一遍**（`kill 主导` / `均衡` / `生存主导`），**只扫一次**；
  最优臂判据 = **门指标最高者**（不是 return 最高者）；三臂全不过 S1 门 ⇒ 记"奖励口径不可判"并停。
- 上报必须带行为指标（击杀/开火效率、受伤数、存活 tick、开火数），**不能只看 return 曲线**。

**S4 奖励（预注册占位，A7 出口定权重）**：

```
R_S4 = R_玩具 + w_base·baseIntegrity Φ + w_safety·baseSafety Φ
```

`baseIntegrity` / `baseSafety` 现成（`rl-reward.ts:116,137`），**只读复用不改常量**。
S4 允许**一次**再扫，扫第二次即违反纪律 7。刷分检查项：**基地失守率、基地承压时长** ——
奖励里一旦有基地项，就要盯"守家不出去"这个反向病理（旧 Φ 的失败形态）。

### 3.5 保底层（混合式）—— 训练期覆盖语义

**为什么需要**：把样本浪费在"别站到子弹前面"这种规则一句话能说清的事上不划算。

**⚠️ 信用分配问题**：保底层触发时 **executed action ≠ 网络采样动作**，而 shard 记的是采样动作及其
logp（`export-rl-rollout.ts:449-473`）⇒ 直接进 PPO 会**污染 importance ratio**。
四条处置，**默认 (e)**：

| 方案 | 做法 | 判定 |
|---|---|---|
| **(e) 独立 dodge 规则（默认）** | 不复用"每 tick 先跑完整 God-AI 链再判 `_lastBranch==='dodge'`"的写法（`goal-executor.ts:204`），改写一个独立 dodge 规则 | 保底层仍在；**不再每 tick 依赖 God-AI 的 think 管线**；省掉部署时的 God-AI 前向；A5 结论变干净 |
| **(c) 接受有偏梯度 + 量化（回退）** | 沿用 God 链 dodge，量化覆盖率 | (e) 的 A/B 显著劣于 God 链 dodge 时才启用 |
| (a) 训练期不启用覆盖 | 干净 | 与本节立意冲突、训练/部署行为不一致 ⇒ 不选 |
| (b) 用 mask 恒定位偷带标记 | 不改 shape | 语义脏 ⇒ 不选 |

**(e) 的可用基元有硬边界（F1 裁定，已核实）** —— 两个函数性质不同：

| 函数 | 实际依赖 | 能否不跑 think() 直接调用 |
|---|---|---|
| `FireControl.scanAheadImpl(self, pcx, pcy, dir, out?)`（`FireControl.ts:185`） | 只读 `self.world` + **纯位置 memo**（`_scanCacheX/Y/Mask`） | ✅ 可以（传 `out` 可完全绕开 memo） |
| `ThreatAssessor.isBaseUnderThreatImpl(self)`（`ThreatAssessor.ts:438`） | 读 `self._baseUnderThreatCache` / `self._enemies`（**think() 填充的每 tick 快照**） | ❌ 不可以 |
| `perception.ts:107` `scanAhead(world, tank, dir, maxDist)` 等 | 只吃 `World` | ✅ 真正独立的世界态基元 |

⇒ **(e) 只准用 `perception.ts` 基元 + `scanAheadImpl`（传 `out` + 单测断言未调 think()）；
禁止 `ThreatAssessor` 及任何读 `_enemies` / `_threatCache` 的函数**。
1.5d 内做不出可用的独立版 ⇒ **直接把 (c) 升为默认并停在此，不超支**。

**覆盖步的记账规则（shape 不变，只改写入内容）**：覆盖发生时，落盘
**executed 动作 + 该动作在采集策略下的 logp**（logits 现成，取对应下标）⇒ PPO 的 ratio 对覆盖步
良定义。⚠️ 备选"从 actor loss 中剔除屏蔽步"在数学上更干净，但需新增 flag 数组 ⇒ 触发止损线 4，
**不作默认**。

**A3 验收四条**：① 覆盖率量化（S1/S2 各 ≥20 局）：<2% 可辩护并记进 progress，≥2% 升级为 P0 决策；
② **受伤数/局的趋势监控**（危害不与步数占比成正比 —— 1% 的关键时刻覆盖足以改变冒险倾向，
若该值随训练上升，即使覆盖率 <2% 也要升级）；③ 与 God 链 dodge 的 A/B（S2 场上比受伤数与存活）；
④ **L0 dodge 覆盖优先于任何路径约束**（保命 > 沿路走）。

### 4.2 最终门的统计功率（A0 出口必须二选一定死）

> **裁定**：2.4pp 是"独立二项"假设下的**上界**。配对设计两臂同 stage 同 seed、结果正相关
> ⇒ 实际 `sd(d)` 应更低。但**低多少必须实测**，不能靠论证。

**A0 出口做功率冒烟**（pinned 基线重跑 1–2 次，用同一 `paired-gate.ts` 测零效应下的 SD/SE/CI；

### 4.3 P1 二元闸（A4b 出口）

**判据**（真实 hard STAGES 0–3，240 局，与随机权重基线**同 seed 配对**，当场判）：

- **过**：胜率 ≥ 随机基线 **+5pp**，**且**中位存活 tick 高于随机基线 ⇒ 继续二阶段（S2–S5）；
- **不过**：停，按止损线 5 二选一写"预算停 / 门败"归因。

这是**无效性闸（futility gate）**，不是成功闸：作用是尽早否掉"迁移不存在"。

#### ⚠️ 缓期与复测点（2026-08-30 补齐，判据本身未改）

### 4.4 六条止损线

1. 某一级在预算内行为指标**不单调上升** ⇒ 该级停，写归因后评估是否继续。
2. **连续两级停** ⇒ 整条梯子停，机时转 T3 / CMA-ES 轨。
3. 目标头解冻前若 headroom（A8a/A8b）**< 3pp** ⇒ 目标轴收官，不进 S5。
4. 全程若发现 obs/动作/shard schema 必须改动才能继续 ⇒ 停，回来改方案（迁移假设破了）。
5. **收场分支必须区分**：① **预算停**（门未判，结论是"未知"而非"失败"，下一步可以是换场/换奖励，
   不必换路线）；② **门败**（结论是否定）。两者下一步不同，**不得混写**。
6. **预算下限**：A7 出口产能核算 `N₁ < N_min` ⇒ **直接写"预算停"，不启动 S4b 的 40h**。
   "预算停"应当是**预测的结论**，不是跑完才补的归因。
