## 0. TL;DR（一页摘要）

- **痛点**：`isBaseUnderThreat()`（GodAIInput.ts:890）类型盲 + 地形盲，导致"任何回防干预都净负"——把缓慢重甲误判成紧急威胁，打断最划算的贴身磨杀。
- **方案**：把"基地威胁判定"从二值开关升级为**每敌威胁分数**（可观测特征）+ **威胁时间分布** `p(t)`（猜测先验的马尔可夫模型），据此选 max 威胁敌，并在其进攻路线中途截杀。
- **落地**：分三阶段，按 ROI/风险递增——**A** 类型/速度/朝向/HP 感知权重（低风）、**B** A* 路线步数+拐弯数（中风）、**C** 中途截杀几何（高风）。全部由参数 `smartThreatModel`（默认 OFF）门控，作为现有基地防御分支的**严格细化**（只在真威胁时覆盖）。
- **泛化保证**：靠 `smartThreatModel` 默认 OFF + 严格细化 + **35×60 off/on A/B** 实测决定"翻全局默认 还是 走覆盖表子集"，而非假设中性。
- **诚实边界**：不偷看敌方 RNG（AGENTS §2.3）；敌人移动用 50/25/25 猜测先验，仅作相对排序器，须经验验证；中途截杀几何最高风险，回归即退回 A+B。

## 1. 背景与诊断

### 1.1 当前成绩（Round 5）
- S32 用覆盖表 `t2aMaxRange:2`（贴身缠斗）+ `campTimeoutTicks:50 / antiCampSuppressTicks:50 / damagedArmorBonus:1 / navStuckTicks:90`，把 43.3% 推到 72.5%。
- 全局 mean 86.9%、0/35 跌破 floor。但 S32 的 base_destroyed 尾部（快车突破开阔底带 21/120=17.5%）与 S6/S18 等防御集群弱关未被解决。

### 1.2 根因：基地威胁判定"两个盲"
`src/ai/GodAIInput.ts` 的 `isBaseUnderThreat()`（890–920）逐行核对后确认：
1. **类型/速度盲**：全程不读 `t.kind`。慢重甲与快车同位置被判为完全相同威胁。唯一区分类型的 `hasFastThreatNearBase()`（928–944）只被 `guardBandMode`（默认 off，S32 也 off，已否决）调用——默认路径对类型完全瞎。
2. **地形盲**：只用曼哈顿距离 `|Δcol|+|Δrow|`，不寻路、不数拐弯、不把钢墙/森林导致的真实绕远算进去。静态框 = 列距基地 ≤3 且 行 ≥18（基地 col12/row24，底部中央约 7×7）；赛跑判定 = `enemyDistToBase ≤ baseRaceRangeCells(11)` 且 `playerDistToBase + margin(0) ≥ enemyDist`。

### 1.3 直接后果：任何回防干预都净负
类型盲让玩家把"缓慢重甲刚进底部框"误判为紧急威胁 → 触发 `skipT2aForDefense`（630–637）打断贴身缠斗、切目标去"防御" → 打断最划算的重甲磨杀。Round 5 验证里，所有回防手段（守卫带 / T2a 跳过 / 限制移动 / aimError=0）在 ≥60 seeds 验证后均否决——都会打断重甲击杀效率导致净负。
**智能模型的核心卖点就是精度**：只在确实存在快速冲家威胁时才选择性去中途截杀它，重甲照磨。

## 2. 问题定义与目标

### 2.1 目标
- 精准识别"真冲家快车"威胁，在其到基地前截杀 → 压低 base_destroyed（S32 向 80% 推、救活 S6/S18 等防御集群）。
- 对无基地压力的 ~25 关保持**行为中性**（不是假设，要实测）。
- 保住重甲磨杀效率（lives_exhausted 不升）。

### 2.2 非目标 / 约束
- **不**调坦克数值（速度/HP/火力由 `INTELLIGENCE_LEVELS` 与 `StageData` 决定，智能等级是配置不是代码）。
- **不**偷看敌方 AI 的 RNG（AGENTS §2.3）；敌人转弯只能观测 / 保守模拟。
- **不**引入每 tick 重决策开销爆炸（sim 已极快，但仍须测量全开时）。

### 2.3 设计原则
1. **数据优于代码**：新行为全由参数门控，默认 OFF 时逐字节等于今天。
2. **严格细化而非新增并行路径**：新逻辑只在"高置信度快速冲家威胁"时覆盖决策，否则走原路径 → 天然隔离回归面。
3. **先验证后推广**：每个 Phase 用 ≥60 seed 对照，泛化用 35×60 A/B。

## 3. 核心设计

### 3.1 威胁评估管线（总览）

```
对每个敌人 e：
  特征 = { 速度, 朝向, HP, 方位, 路线步数, 拐弯数 }      // §3.2 / §3.3
  时间分布 p_e(t) = P(e 在 t 前首次进入 canShootBaseFrom 格)  // §3.4 / §3.6
  threatScore(e) = w · 特征 + 时间项( P_threat(K) 或 1/expectedTime )  // §3.6 落地

按 threatScore 降序排序 → 选 e* = argmax
  if e* 满足"真冲家快车" 且 存在可行截杀点 I* (slack>0):   // §3.7
        → 漫游截杀（Phase C，最高风险）
  else if e* 是冲家威胁:
        → 换目标追猎 + T8 子弹拦截兜底（当前行为）
  else:
        → 照常猎杀（行为不变）
```

### 3.2 可观测威胁特征（Phase A）
全部来自 World 状态（纯函数、不碰确定性）：
- **速度**：`kind` → `baseSpeedPxPerTick(kind)`。快车权重高，重甲低（重甲本就该贴脸磨）。
- **朝向**：敌人 `facing` 与（基地−敌人）方向点积。朝基地 = 高，背对 = 低。
- **HP**：`shotsToKill = ceil(hp / 玩家DPS)`。1 血快车"一枪解决"= 低持续威胁；4 血重甲 = 长交火。
- **方位**：到基地曼哈顿距离（保留为基础项）。

### 3.3 路线特征（Phase B）
- 对敌人跑一次 A*（`enemyCell → baseAdjacentCell`），返回**步数 + 拐弯数**（拐弯数 = 路径上连续方向变化次数，与步数同由 A* 免费得到）。
- 路线短 + 拐弯少 = 敌人能高效抵近基地 = 高威胁。
- **关键区分**：这是瓦片代价模型下的最短路径，描述"从这里到基地有多通畅"的**地形属性**，不是敌人未来实际轨迹（敌人移动随机、由敌方 RNG 决定，God AI 不可观测）。别把"最短路径拐弯数"当成"敌人真实拐弯数"去预测——它只是代理特征。
- 开销：低频重算（敌每移动一格或每 N tick），不做每 tick 每敌 A*。

### 3.4 敌人移动先验与威胁时间分布（猜测模型）
**不偷看敌方 AI 决策**（AGENTS §2.3）。为威胁评估 / 中途截杀，显式、可调地**猜测**敌人移动（用户 2026-07-29 提出）：
- **转弯先验**：敌人在"决策点"（当前前进方向被障碍挡住时）按 A* 通路正确方向 **50%**、垂直两方向**各 25%**（3 候选 50/25/25；某向封死则在该格可用方向内归一化）。
- **持续直行**：选定方向后一直直行到有障碍才下一次转弯；不考虑将来墙被拆。
- 形成**走廊随机游走**：决策点只在前进被挡格，决策间是段段直行。

由此形式化为以 `(格子, 朝向)` 为状态的**马尔可夫链**：
- 正前格可通行 → 确定移到 `(cell+朝向, 朝向)`（t+1），除非该格属"能射击基地格"（吸收=威胁达成）；
- 正前格被挡 → 按 50/25/25 重采样新朝向（t+1）。时间步权重乘敌人种类速度（fast 每格更少 tick）。
- 两敌独立 → 各敌分布天然可在公共时域 t 上横向比较（"同一时刻"）。

### 3.5 "能射击基地位置"精确定义（canShootBaseFrom）
用户 2026-07-29 两条件，写成谓词 `canShootBaseFrom(cell)`：
1. **对齐**：cell 与基地同 row 或同 col（= 去掉所有障碍后能直射基地）；
2. **当前障碍下 4 连发可达**：沿 cell→基地直线，① 无钢铁遮挡，② 砖墙数 ≤ 3（每砖 1 发打穿，3 砖=3 发清通+第 4 发命中；0 砖=1 发即中）。坦克等动态障碍不计入本静态判定。
- 条件二已蕴含条件一 → 实际只测条件二。
- 例：cell 与基地间有钢铁 → 不满足；之间仅 3 块砖 → 满足。
- 此定义比"仅现有开口"更宽（允许 4 发拆砖命中），是更大、更准的威胁候选集；仍只看当前分布，不预测敌人先拆路径外砖块（高阶效应，忽略）。
- DP/MC 的**吸收态** = 敌人首次进入 `canShootBaseFrom` 为真的格子。

### 3.6 时间分布求法（DP 精确 / MC 近似）
1. **动态规划（精确、确定性，推荐）**：状态空间 `(cell, heading, t)`，网格 26×26 × 4 朝向 × 时域 ~300 tick ≈ 80 万状态，有限时域递推得 `P(在 t 前到达能射击基地格)` 的 CDF；PDF `p(t)` 即"在 t 时刻到达的概率"。**不消耗 `world.rng`**，是 World 状态的纯函数 → 满足 parity / §2.3。
2. **蒙特卡洛前向模拟（近似）**：每敌跑 N 次（~200–1000）随机前向模拟至到达或超时，聚合 (t, p) 分布。**必须用本地固定种子 PRNG**（seed = enemyId + tick），**禁止消费 `world.rng`**。
3. **廉价近似（可先用）**：因直行持续，沿 A* 路径"始终不早拐"概率 ≈ `0.5^(A* 决策点数)`；期望时间 ≈ `A*步数 / 速度`。Phase B 已算 A*，近乎免费，可能已够；完整分布是 refinement。

**落地为威胁分数（把分布压成一维）**：取标量如 `expectedTime = Σ t·p(t)`、`P_threat(K) = P(在 K tick 内到达)`、或危险率 `hazard(t)=p(t)/P(未到)`。用 `P_threat(K)` 或 `1/expectedTime` 作时间项，喂给 §3.2 打分与 §3.7 截杀选择。

### 3.7 中途截杀几何（Phase C）
把 §3.4/§3.6 的每敌 `p(t)` 转成**具体截杀格 + 出发时机**：
- **输入**：玩家当前格 `P0`；敌人 A* 路线 `R`（§3.3）；`p(t)`（§3.6）。
- 对每个候选截杀格 `I`（取 `R` 上及其邻域）：
  - `t_E(I)`：敌人到 `I` 的时间分布 ≈ `p(t − δ)`（δ = `I` 到最近 base-shoot 格的路线时间，把到达分布前移）。
  - `t_P(I)`：玩家从 `P0` 经玩家 A* 到 `I` 的旅行时间（玩家可走集：砖/钢挡移动；砖可拆按每砖 +T 罚时作 refinement）。
  - **slack(I) = t_E(I)_low − t_P(I)`**，取 `t_E(I)_low` = 期望到达或 25 分位（要玩家"提前到有裕度"）。**可行 ⇔ slack(I) > 0**。
  - **选 `I* = argmax_{可行} slack(I)`**：裕度最大 = 最远离基地、最早安全 = 最佳截杀点。
- **击杀机制**：玩家驻守 `I*`，敌人在 `aimRange`（沿用 t2aMaxRange 或标准值）内对齐即开火；快车 1 发解决 → 敌到基地前已移除。把 t2aMaxRange=2 从"在目标旁死等"升级为"去敌人必经之路等"。
- **多威胁护栏（必须）**：仅当所选敌 `threatScore` 占优（明显高于次敌）且 `I*` 可行（slack>0）才启动漫游截杀；否则退回"优先级换目标 + T8 子弹拦截"兜底。T8 始终保留作最后防线。

## 4. 增量落地（Phase A / B / C）

### 4.1 Phase A — 类型/速度/朝向/HP 感知权重 + 类型感知 isBaseUnderThreat（先做，最高 ROI/最低风险）
**改动**：
- 新增参数 `smartThreatModel`（默认 false）。false 时 `isBaseUnderThreat` + `selectTargetImpl` base-threat 分支**逐字节等于今天**。
- true 时：
  1. `isBaseUnderThreat()` 改为：存在 `threatScore(e) ≥ smartThreatThreshold` 的敌（且在其威胁范围内）即为威胁。分数用 §3.2 四特征。
  2. `selectTargetImpl` base-threat 分支（319–365）改用 `threatScore` 排序，而非当前 `distToBase + KIND_THREAT_WEIGHT + urgencyBonus + proximityBonus`。
  3. `skipT2aForDefense`（630–637）仅当威胁是**真冲家快车**时才打断贴身缠斗 → 保住重甲磨杀。
- 权重初值人工设定，随后 CMA-ES（或手调）+ 60-seed A/B 定标。
- **先只通过 S32 覆盖表开启**（`smartThreatModel: true`），验证 S32 是否向 80% 推且不破坏重甲磨杀。
**验收**：S32 @120 seeds ≥80%（或明显 >72.5% 且 base_destroyed 续降）；重甲击杀率不降（lives_exhausted 不升）。

### 4.2 Phase B — 路线/拐弯数特征（中等）
- 新增 `enemyRouteToBase(t)`：`findPath(enemyCell → baseAdjacentCell)`，返回步数 + 拐弯数；低频重算（敌每移动一格或每 N tick）。
- 将 `routeSteps`、`turnCount` 并入 `threatScore`（路线短/拐弯少 = 高威胁）。仅在 `smartThreatModel` 开启时计算。
**验收**：防御集群关（S6/S18/S32）@60 seeds 是否续升；强关是否仍中性。

### 4.3 Phase C — 中途截杀几何（坦克版 T8，最高风险，放最后）
- 新增 T 分支（如 `T9 tank interception`）：当存在高威胁快车且玩家能在它到基地前截住时（§3.7 的 `I*` 可行），移动过去开火。改编 `predictEnemyCrossingImpl`（FireControl.ts:199）与 `baseBulletInterceptCell`（ThreatAssessor.ts:127）。
- **必须轨迹预测，不能是固定位置**（旧 `interceptCell` 因"坐防御行等敌人穿过→玩家干等"被废弃）。
- 只在防御集群关先验证；若回归就退回 A+B（追猎 + 精确选择已够）。
**验收**：防御集群关 base_destroyed 显著下降；不得引入"玩家干等/乱跑"新失败模式（parity + 轨迹抽查）。

### 4.4 计算开销预算
- 每敌每 tick 全量 DP/MC 太贵 → 低频重算（敌每移动一格或每 N tick 缓存分布）。
- sim 已极快（perTick ~0.02ms，headless bench p95<1µs），但 35 关全开 + 每敌 A* + 前向模拟须实测帧耗时，必要时降频重算或降采样 N。

## 5. 泛化策略

### 5.1 失败模式映射（智能模型只救"基地被拆"家族）
- **基地被拆主导**（快车/侧翼冲家）：S6(12 GO)、S18(12 GO)、S32(15 GO)，外加 S7/S5/S10/S20/S21/S27 等混合 GO。智能模型直接对症。
- **命数耗尽主导**（导航/瞄准瘫痪，基地几乎不倒）：S26（覆盖表注释 *"base almost never falls"*）、S9/S3/S4/S11/S28/S33 等。智能基地防御对其几乎零收益——问题是杀不够/卡死，不是基地被拆。
- 已 95–100% 关（S1/S2/S9/S13/S17…）：期望中性（行为不变），任何下降都是回归。
- → "泛化到全 35 关"的真正含义：**救活基地防御子集（约 6–10 关），对其余 ~25 关保持中性。**

### 5.2 为何比 `t2aMaxRange` 易泛化
`t2aMaxRange=2` 只能 S32 专用（贴脸才开火在需远程火力的关是负收益）。智能威胁模型是"正确的防御行为"：有真威胁才精确防御、无威胁照常猎杀。理论上任何有基地压力的关受益、无压力关中性的，泛化面好得多——但"无压力关中性的"必须工程化保证 + 实测确认，不能假设。

### 5.3 安全泛化三件套
1. **参数门控、默认 OFF**：`smartThreatModel` 默认 false → 全局行为逐位不变（与 `t2aMaxRange` / `guardBandMode` 同模式，data over code）。
2. **严格细化**：新逻辑只在检测到"高置信度快速冲家威胁"时覆盖决策；无威胁/常规猎杀路径逐字节不变 → 20+ 关行为完全不变。
3. **35×60 off/on A/B** 决定落地方式（见 §5.4）。

### 5.4 落地方式决策（由数据驱动）
- 救起防御集群 且 强关仅 ±1–2pp 噪声 → **默认翻 ON**（真·全局泛化）。
- 只子集受益 → 写统一过滤逻辑（如钢/砖比、森林/水域密度等关卡特征阈值，见 `computeStageAdaptedParams()`）；逐关名覆盖表已禁用（DECISIONS §81），防止过拟合。
- 某强关掉 ≥5pp → 模型有 bug 或过度激活，回炉。

## 6. 验证与门禁协议（沿用 P4 方法论，对后续有约束力）

1. **单关改动 ≥60 seeds 对照**（新行为 vs 同 base 无新行为）。20-seed 只能筛选、不能定论（二项噪声 ±11pp）。
2. **泛化必须用 35×60 off/on A/B**：确认 mean 不降、无关跌破 floor、弱关（防御集群）上升。
3. **回归门禁必须升级以保护环境增益**：`tests/god-ai-regression-gate.test.ts` 当前 35×20、逐关 floor = 60-seed 真值 −4 wins、聚合 77%。若 Phase A/B/C 抬升了某关（如 S32），其 truth 必须同步更新（参考 Round 5 把 S32 51.7→72.5 的修正），**禁止静默降 floor 掩盖回归**。
4. **Parity 重锁**：`tests/godai-split-parity.test.ts` 在改动 `think()` / `selectTargetImpl` 行为后必须重锁（§0.5 仅保证拆分零漂移，不覆盖行为改动）。
5. **确定性**：God AI 决策必须是 World 状态纯函数，不得调用 `Math.random()`（AGENTS §2.3）。敌人转弯概率只能观测 / 保守模拟，不能偷看敌方 RNG。

## 7. 风险登记

| 风险 | 等级 | 缓解 |
|------|------|------|
| 50/25/25 猜测先验 ≠ 敌方真实策略（真实 `TacticalIntelligence` 有自身目标/避让/出生带） | 中 | 仅作**相对排序器**；须验证"按此排序是否真预测拆家"；不字面预测 |
| 中途截杀几何脆弱（随机转弯使轨迹预测易碎） | 高 | 保守前向模拟 + 实测校准；`I*` 锁在 A* 路线+基地咽喉；保留 T8 兜底 |
| 玩家漫游暴露基地给 2nd 威胁 | 高 | 占优门限 + T8 子弹拦截兜底 |
| 移动开销 vs 击杀别的目标 | 中 | 仅 `threatScore` 明显最高时启动漫游 |
| 每 tick 开销（A* + 前向模拟） | 中 | 低频重算 / 缓存分布；全开时实测帧耗时 |
| "中性"是假设不是保证（P4 教训：一关 +15pp 可能伴另一关 −30pp @60seed） | 高 | 35×60 A/B 是证伪手段，不是形式 |
| 现有覆盖表 S6/S18/S25/S26 的 tuned 项可能与新模型重叠 | 低 | 验证后决定保留还是精简，不预设 |
| Phase C 引入"玩家干等/乱跑"新失败模式 | 高 | 35×60 A/B + 轨迹审计；回归即退回 A+B |

## 8. 执行路线与决策门

**首个动作**：实现 **Phase A**（`smartThreatModel` 默认 OFF 参数 + 打分/判定改造 + S32 覆盖开启），然后跑一轮 **35×60 off/on A/B**，用数据回答：
1. 能否安全泛化（强关中性、弱关上升）？
2. 哪些关真正受益（决定翻全局默认 vs 覆盖表子集）？
3. 是否值得继续做 Phase B/C？

**决策门**：
- Phase A 在 S32 验证正向且不破坏重甲磨杀 → 进 Phase B。
- Phase B 在防御集群关续升、强关中性 → 进 Phase C（截杀几何）。
- 任意 Phase 在 35×60 A/B 出现强关掉 ≥5pp 或新失败模式 → 回退上一阶段，保持已验证增益。
