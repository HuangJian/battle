# 如何给 DECISIONS.md 加一条（决策治理，2026-09-08 起执行）

> 完整背景见 `plan/decisions-governance.md`。写之前先过下面的闸门——多数时候结论是「不写」。

## 0. 三问闸门（有一问答 No，就不写 DECISIONS.md）

| # | 问题 | 答 No 意味着 |
|---|---|---|
| 1 | 有没有**被否决的备选方案**？ | 那是执行，不是决策（bugfix / UI 调整天然全灭）。 |
| 2 | 未来 agent 会不会**重犯或重查**？ | 不会 → 不记。会 → 记，但优先进「勿重提清单」。 |
| 3 | **能不能就近表达**？ | 代码注释 / 测试断言 / 配置字段名 / docstring 能说清的，不进中央文件。 |

## 1. 三类内容各自去处

- 决策 / 禁令 / 铁律（不可逆、有被否决备选、防重犯）→ **DECISIONS.md**（占编号）
- 实验记录 / 参数调优 / 探针结论 → `docs/**.progress.md`（**不占编号，禁止双写**）
- bugfix / UI 调整 / 运维清理 → 只写 **commit message**（要防重犯的落成测试断言）
- 临时上下文 → `.workbuddy/memory/YYYY-MM-DD.md`

## 2. 新条目 ID 与模板（≤12 行）

ID：`§YYYY-MM-DD-<branch>-<slug>`（branch 去连字符，如 `god-ai` → `godai`；
同日同分支第 N 条加 `-2`）。旧编号 §1–§384 是历史契约：**永不重排、永不删除**。

```markdown
## §2026-09-08-<branch>-<slug>（<日期>，<触发来源>）

- **背景**：<2 行>
- **备选与否决**：<A —— 否，因为…；B —— 否，因为…>（必填，填不出=不是决策）
- **决定**：<1–3 行>
- **违反后果**：<不这么做会怎样，1 行>
```

## 3. 规则

- 只追加：新条目只写文件**末尾**，禁止中部插入（合并冲突靠 `.gitattributes` union）。
- 被取代的条目标 `_(superseded by §ID)_`，永不删除。
- 正确性由 `bun run check` 里的 `tools/check-decisions.ts` 强制（撞号 / 丢号 / 格式）。
